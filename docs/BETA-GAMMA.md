# β–γ 图：两种存能能力的二维平面

> 状态：**认知已建立，尚未实现**。本文只记录定义、口径、与内核的对应关系、实算值与实现路径，
> 供拍板。第一张图（ΔV–BC 散点 + 等时线）在本仓库已经完成，见 `figures/`。

## 1. 两个坐标轴的定义

β–γ 图是导弹**两种存能能力**的二维能力平面：横轴管"直飞"，纵轴管"转向"，两轴互相独立。

| 轴 | 公式 | 物理含义 |
| --- | --- | --- |
| **β（横轴）** | `m_燃尽 / (SD · CxK)`，`SD = π·d²/4` | **直飞保能** |
| **γ（纵轴）** | `m_燃尽 · SD · CxK · CxAoA / (SL² · CyK²)`，`SL = 0.3·d·L·w` | **转向损失** |

两者都 ∝ 燃尽质量 `m`，但分母不同 —— β 由口径与 `CxK` 决定，γ 由升力面积平方与 `CyK²` 决定。
**数学上互不包含（β 甚至不含 `wingAreaMult`）**，这是它能当二维平面的前提。

### 1.1 与内核的一一对应

`SD` 与 `SL` 不是我们另造的量，它们**就是内核自己的两个面积**（`vendor/wt-missile/wt_missile.py`）：

| 本文符号 | 内核字段 | 出处 |
| --- | --- | --- |
| `SD` | `self.drag_area = math.pi * d * d / 4` | `wt_missile.py:758` |
| `SL` | `self.lift_area = 0.3 * d * L * w` | `wt_missile.py:757` |
| `CxK` | `p["CxK"]`（blk 里有） | `wt_missile.py:810` |
| `CyK` | `p.get("CyK", 2.2)` | `wt_missile.py:760` |
| `CxAoA` | `p.get('CxAoA', 9.0)` | `wt_missile.py:780` |

`SL = 0.3·d·L·w` 与内核 `lift_area` **逐字一致** —— γ 的升力面积口径直接继承内核，没有自由参数。

### 1.2 γ 为什么长这样（从内核阻力式反推）

内核的阻力（`wt_missile.py:810`）：

```python
drag = dynamic_pressure * self.drag_area * p["CxK"] * (fm + induced * sin2)
```

展开成两项：

```text
drag = q·SD·CxK·fm  +  q·SD·CxK·induced·sin²α
```

而升力（`wt_missile.py:803-806`）：

```python
cy = self.cy * math.sqrt(sin2)          # CyK·sinα
lift = cy * dynamic_pressure * self.lift_area
```

即 `L = CyK·sinα·q·SL`，反解出 `sinα = L / (CyK·q·SL)`。代入诱导项：

```text
D_induced = q·SD·CxK·induced·sin²α
          = SD·CxK·induced·L² / (CyK²·q·SL²)
a_induced = D_induced / m
          = SD·CxK·induced·L² / (m·CyK²·q·SL²)
```

取标准转弯 `L = n·m·g`，则 `L²/m = n²·m·g²`：

```text
a_induced = n² · [ m·SD·CxK·induced / (SL²·CyK²) ] · (g²/q)
```

方括号里就是"**单位过载平方的转向能量代价**"，取 `induced ≈ CxAoA`（标称）即得本文的 γ。
**所以 γ 是"转向损失"，不是"诱导阻力减速度的倒数"** —— 两者相差 `L²` 与 `CyK²·SL²` 的换算，
这是本轮认知里最容易搞错的一处，特此记下。

### 2.1 三条已验证的结论

1. **`β` 与现有 `BC` 逐值相同（11/11）**。因为 `BC = m_dry/(CxK·SD)`（`mapping.blk_metrics`）
   与 `β = m_燃尽/(SD·CxK)` 是同一个式子。⇒ **第二张图的横轴就是第一张图的纵轴**，两图同源。
2. **两轴没有退化**：β 跨度 43.5%、γ 跨度 70.5%，**皮尔逊相关系数 −0.51** ——
   存在"直飞保能 ↔ 转向保能"的取舍，但远不是一条直线，散点能铺成平面。
   例：R-77 β 最低（2568.8）而 γ 最高（91.2）；AAM-4 β 最高（3683.9）γ 也高（89.3）；
   PL-12/PL-12A 靠大 `wingAreaMult`（1.8）把 γ 压到 56.6/59.7 —— 这正是它相对 AAM-4 的取舍点。
3. **γ 的分散主要来自 `SL²`**（即 `wingAreaMult²`）：把 γ 乘回 `w²` 后离散度从 70.5% 降到 58.4%，
   说明 `w` 是显著但不是唯一的贡献者（口径 `d`、长度 `L`、`CxK` 也在起作用）。

### 2.2 ⚠ 一个必须知道的数据事实

**`CxAoA` 与 `CyK` 在 11 型的 blk 里都不存在**（实测 `"CxAoA" in params` 恒为 `False`），
内核分别用兜底常量 **9.0** 与 **2.2**。含义：

* 11 弹的 `CxAoA`、`CyK` **完全相同** ⇒ 它们不贡献任何横向差异，γ 的差异全部来自
  `m_燃尽`、`SD`、`CxK`、`SL`（即 `d`、`L`、`w`）。
* 若将来把这两个量做成可调旋钮，那是**引入内核默认值之外的假设**，
  必须在图上与 `results/*.json` 里写明口径，不能让它看起来像 blk 里的实测数据。

## 3. 口径选择（须与第一张图保持一致）

内核的阻力式里还有一个 **Mach 修正因子 `fm`**（`_mach_function`，实测在 `0.302~0.615` 之间，
即随 Mach 变化约 2 倍），而 `induced` 自身也是 `fm` 的线性函数（`useCxiMach=True`）。

| 口径 | β | γ | 后果 |
| --- | --- | --- | --- |
| **标称（本文采用）** | `m/(SD·CxK)` | `m·SD·CxK·CxAoA/(SL²·CyK²)` | 与现有 BC 一致；是**每个弹一个定值**，可直接做散点 |
| 含 Mach（内核真实值） | `m/(SD·CxK·fm)` | `m·SD·CxK·induced·…·` | 随 Mach 变化 2 倍，**不是定值**，无法当坐标轴 |

**结论：β–γ 图必须用标称口径。** 这与第一张图把 BC 定义成不含 `fm` 的做法一致。
（顺带一个已验证的细节：`γ/β` 在真实口径下 = `fm/induced` ∈ `[0.306, 0.352]`，
全程只差 ±7% —— 两轴的 Mach 敏感度高度同步，所以标称口径不会扭曲两轴的相对关系。）

## 4. 实现路径（可行性已确认）

### 4.1 扫描所需的反解

要把一个点放到 β–γ 平面的 `(β_t, γ_t)` 上，只需缩放**两个内核参数**，其余全不动：

```text
cx_scale     = CxK_new / CxK_blk = β_blk / β_t
CxK_new      = m_燃尽 / (SD · β_t)
CxAoA_new    = γ_t · SL² · CyK² / (m_燃尽 · SD · CxK_new)
cxaoa_scale  = CxAoA_new / CxAoA_blk            （CxAoA_blk = 内核兜底 9.0）
```

**这是双射**：`(CxK, CxAoA) ↔ (β, γ)`，两轴独立可达，正是二维扫描要的性质。

把 `CxK_new` 代进 `CxAoA_new` 的表达式，`SD` 会被约掉，得到一条更干净的关系：

```text
CxAoA_new  = γ_t · β_t · SL² · CyK² / m_燃尽²
⇒ cxaoa_scale = CxAoA_new / CxAoA_blk = (γ_t / γ_blk) / (β_blk / β_t)
              = (γ_t / γ_blk) / cx_scale
```

直觉：β 变小 ⇒ 该点 `CxK` 变大（`cx_scale = β_blk/β_t > 1`），而 γ ∝ `CxK·CxAoA`，
所以要维持同一个 γ，`CxAoA` 必须**按同样比例缩小**。落到代码就是 `bg.cxaoa_scale_for()`
（它收调用方给的 `cx_scale`，不自己再算一遍 `β_blk/β_t`，免得出现第二套口径）。

### 4.2 注入点：`solver._apply()` ＋ `_patch_profile()`（**扩了一个分支，并修掉一个静默 no-op**）

乘子注入走 `solver._apply()`：它包装模块级 `wt_missile.load_profile`，在 `complete()` 里按
`upd` 字典乘 `force`/`force1`/`CxK`/`CxAoA`，再交给 `_patch_profile()` 写回，
`finally` 里恢复原函数。

* **扩 `CxAoA` 就是同一个模式**：在 `upd` 里多写一个 `CxAoA` 键。
* ⚠ **`_patch_profile()` 的 `walk()` 只能改"已经存在的键"** —— 它遍历的是 `node.items()`。
  第一版照着"直接赋值就能新增键"的假设写，而 11 型 blk 里**都没有** `CxAoA`，
  于是注入是**静默 no-op**：不报错、不生效，结果看起来完全正常。
  症状是 γ 轴在图上**完全不动**，逐位相同（`t_hit = 45.185932964507536` 三个 γ 一字不差）。
  现在 `_patch_profile()` 末尾有"补缺"分支：`updates` 里 blk 没有的键补在**顶层**，
  内核就是从顶层读这些字段的。
* **写进去的是"有效值"**：内核读的是 `p.get('CxAoA', 9.0) × (wingAreaMult² if
  applyWingAreaMultToCxAoA)`。所以 `solver.effective_cx_aoa()` 先把这条规则算准，
  并在注入时**顺手把 `applyWingAreaMultToCxAoA` 关掉**，免得内核再乘一次。
  11 型实测该开关全是 `False`，对它们是恒等变换；正确性由 `tests/test_bg_scan.py`
  对着 `solver.body_aero()` 逐弹对拍守住。
* 内核每次调用 `load_profile` 都重新解析（"只乘一次，不会累积"），
  因此 `Body.cx_aoa`（在 `Body.__init__` 里缓存）**每次求解都会用新值重建**。

实际改动的类型：`spec.Scaling` 加一个 `cxaoa_scale` 字段（默认 1.0，老产物 `from_dict` 不会炸）、
反解放 `bg.scaling_for()` / `bg.cxaoa_scale_for()`（β–γ 是 `bg` 的域，不是 `mapping` 的）、
`engine.Engine(scaling_of=…)` 这个口子让"一个格点怎么落到求解器上"可替换、
`engine.cache_key()` **改为吃整块 `Scaling`**（`CACHE_SCHEMA` 3 → 4）。
最后一条是硬要求：旧键里只有 `(ΔV, BC)` 两个数，同一列（同 β、不同 γ）会互相命中缓存。

反解的代数（`cxaoa_scale = (γ_t/γ_blk) / cx_scale`）与三处不动点的自洽性由
`tests/test_bg_scan.py` 的 `test_scaling_round_trips_back_to_the_target_beta_gamma` 守住。

### 4.3 与第一张图的关系

* 横轴 β **就是**第一张图的纵轴 BC ⇒ 两张图共享一个坐标轴，天然可比。
* 第一张图扫 `(ΔV, BC)`，第二张图扫 `(β, γ)`：前者是"能量 × 零升气动"，
  后者是"零升气动 × 诱导气动"。**两者互补**，且第二张图固定 ΔV。
* 实现上直接复用第一张图的链路：`grid.make_grid` / `grid.t_hit_matrix` /
  `grid.extract_isolines` / `Engine.many` / 三格式字节可复现保存。
  差别只有三处：`Engine(scaling_of=bg.scaling_for)`、列名写 β/γ、`monotonic_report` 要
  分别看两个方向（β 递减、γ 递增）。表单契约、自适应轴、后台任务 + 进度条都是照搬。

## 5. 派生指标：`Q` / `n*` / `R` / `β_eff`

β、γ 是**固有量**（不含工况）。但"谁更耐机动"要引入动压，于是有下面一族派生量。

把 `sinα` 换成过载（`L = q·SL·CyK·sinα`，`n ≡ L/(m·g0)`）后代回诱导项：

```text
a_loss = q·f(M)/β  +  γ·F(M)·(n·g0)²/q
         └基础项┘     └── 诱导阻力项 ──┘
F(M) = 3.247·[0.308 + 0.75·(f(M) − 0.308)]        ← 就是内核的 induced/cx_aoa
```

两项对动压的依赖**方向相反**（`a_base ∝ q`、`a_aoa ∝ 1/q`）—— 高空高速基础阻力主导，
低空低速机动阻力主导。这解释了"高空打远、低空缠斗"的能量表现差异。

| 指标 | 公式 | 单位 | 含义 |
| --- | --- | --- | --- |
| `Q` | `√(β·γ·F(M)/f(M))` | kg/m² | **机动敏感度**，越小越好 |
| `n*` | `q / (Q·g0)` | G | **临界过载**：机动损失恰好等于基础损失 |
| `R` | `(n/n*)² = (Q·n·g0/q)²` | — | **机动惩罚比**；`R=1` 时两项等量 |
| `β_eff` | `β / (1 + R)` | kg/m² | **等效弹道系数**，把机动折回 BC 口径 |

**`Q` 最适合当坐标轴**：`F/f` 实测只在 `2.889~3.263` 之间波动（±6%），所以 `Q` 近似与马赫数
无关，接近"弹的固有属性"；而 `β_eff` 依赖工况 `(h, V)`，换高度速度数值全变。`n*` 最直观
（单位是 G，"数字越小机动越贵"），但 `n* ∝ q`，必须标注工况。

### 5.2 等值线 = 等 `n*` 线（参考图的核心机制）

由 `n* = q/(Q·g0)` 与 `Q = √(βγF/f)` 反解：

```text
n* = q / (g0 · √(β·γ·F/f))
⇒  γ = (q / (n*·g0))² · (f/F) / β
```

**所以等 `n*` 线是双曲线 `γ ∝ 1/β`**（不是直线，也不是等间距）。

### 5.3 适用边界（不可越界）

1. **仅升力线性段**（`CyK·sinα ≤ CyMaxAoA`）—— 超过峰值后升力下降，不能再用 `sinα = m·n·g0/(q·SL·CyK)` 反推。
2. **准平衡、无角速度** —— 非零 `ω` 会通过作用点局部来流改变有效迎角。
3. `n` 是**实际气动过载**，不是飞控请求过载，也不含推力矢量贡献。
4. **`β`、`γ` 都含质量 `m`，口径必须写明** —— 本项目与散点图统一用**最终燃尽质量**
   （双级发动机要按 `timeFire`/`timeFire1` 推进，只取 `massEnd` 会错：PL-12 会得到 3731 而不是 3078）。
5. **`F(M)` 依赖 `useCxiMach`** —— 该开关关闭时 `F = 1`（11 型实测全为 `True`）。
6. **`CxAoA` 取内核值** —— 11 型 blk 都没有这个字段，内核兜底 9.0；若某型显式配置则以该值为准。
7. ⚠ **"命中时间"这种指标在几乎不机动的工况下看不见 γ**（实测结论，不是推测）。
   50 km 迎头、双方 300 m/s、10 km 高、`observation=ideal` 的默认工况下：
   固定 β 把 γ 从 45 拉到 100，`t_hit` 只动 0.37 s（45.11 → 45.48），
   而固定 γ 把 β 从 2600 拉到 3700，`t_hit` 动 4.3 s —— **等时线在图上近乎竖直**。
   这正是 `a_loss = q·f/β + γ·F·(n·g0)²/q` 里"低过载时基础项主导"的直接体现。
   `tests/test_bg_scan.py::test_beta_matters_more_than_gamma_for_hit_time_in_a_straight_flying_scene`
   把这条钉住了；图上脚注也如实写了读法（否则看图的人会以为 γ 轴画错了）。
   γ 要显出来需要**高过载需求**：离轴发射、机动目标。40° 离轴那一档已经能看到 γ=100 直接脱靶
   （`lifetime` 事件）。**机动目标已验证可行**（见 `docs/MANEUVER-TARGETS.md`）：目标 6G 转弯时
   γ 40→140 使 t_hit 散开 3.0 s（直飞只有 0.67 s），8G 时散开 10.4 s 并出现命中/脱靶边界。

## 8. 待拍板（现状：都已给默认值，可改）

> 下面 6 条**本轮全部按"参考图口径 + 可覆盖"落了默认值**，不再是阻塞项。
> 每条都写清了默认值与改法；需要改哪条，说一声即可。

1. **图上画什么**：默认**两层都画** —— 参考图那一套（11 弹气泡 + 等 `n*` 双曲线）作底层，
   仿真等时线作上层。不要仿真层就 `--bg-no-scan`。
   ⚠ **四象限底色已按用户要求删除**（2026-09-29，见 §6 第 3 条"三处刻意的不沿用"）。
   ⚠ 注意 §5.3 第 7 条：直飞工况下等时线近乎竖直，γ 轴在仿真层里几乎不动 —— 这是物理，不是 bug。
   想让 γ 动起来要引入机动目标（可行性已验证，见 `docs/MANEUVER-TARGETS.md`）。
2. **扫描范围与步长**：沿用"自适应轴 + 固定步长"，默认 β 步长 30、γ 步长 2、等时线 1 s
   （→ 43×24 = 1032 工况）。`--beta-step` / `--gamma-step` / `--iso-step` 可改。
3. **ΔV 怎么固定**：默认取**基准弹标称 ΔV**（PL-12 = 932.57 m/s），`--bg-dv` 可覆盖；
   manifest 里 `scan.dv_pin_ms` 记着用的是哪个，图注也写明是"用户指定"还是"基准弹标称"。
4. **`CxAoA`/`CyK` 是否暴露成用户旋钮**：**不暴露**。它们是内核兜底值，暴露等于把内核内部假设
   变成用户输入；β–γ 扫描已经用 `β_t`/`γ_t` 这两个物理量覆盖了同一条自由度。
   需要单弹调参时改 `bg.scaling_for()` 的反解，而不是往表单加框。
5. **基准弹**：默认 PL-12（与第一张图一致），`--standard` 可改。基准弹决定仿真层网格跑谁、
   以及 ΔV 默认固定成多少。
6. **参考工况是否可改**：默认 10 km / 800 m/s（与参考图一致），`--bg-alt` / `--bg-speed` 可改。
   改它**不动任何散点**（β、γ 是固有量），只移动等 `n*` 线族与 R/β_eff；副标题与 manifest
   都跟着写新值，所以不会出现"图注和线不一致"。
   ⚠ 表单/CLI 上这两个量叫 `bg_alt_m` / `bg_speed_ms`，**不能**复用 `alt_m`
   （那是载机发射高度，见 §4.2 与 `cli._BG_ALIASES` 的注释）。
