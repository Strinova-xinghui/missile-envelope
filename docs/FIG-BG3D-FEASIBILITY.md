## 0. 一句话结论

**技术上完全能出（零新依赖，5000 工况扫描约 2 分钟、提 6 张等值面 101 ms），
但这个想定下三维信息量很小**：等值面是一族**近似平行的板**（逐 (β,γ) 列直线拟合，ΔV 方向
`R²` 中位 **0.9893**、斜率相对散布仅 **3.0%**），ΔV 轴上真正独立的东西只有一个数
**`b ≈ −0.0336 s/(m/s)`**；而且按三轴真实跨度画会糊成一块板（第 6 张面只剩 **18%** 可见），
必须改成**等长三轴 + 半透明**才看得清（`spikes/bg3d/out/iso/v8_cube_six.png`）。
**建议先不把它做成图4**；如果要做，用『2D 等时线 + 一张 ΔV–t_hit 斜率表』能拿到同样的信息量。

## 1. 数据层：ΔV 是怎么变成第三根轴的

三根轴的参数化**只用了既有出口**，没有碰内核契约（`vendor/`、`solver.py`）：

| 轴 | 出口 | 说明 |
| --- | --- | --- |
| β | `bg.scaling_for(p, m, beta=…)` → `cx_scale` | 与图2 同一口径 |
| γ | 同上 → `cxaoa_scale` | 由不变量 `cx_scale·cxaoa_scale = γ/γ_blk` 顶住 |
| **ΔV** | 同上 → `thrust_scale = ΔV/ΔV_blk` | `thrust_scale` **严格只受 ΔV 影响** |

`bg3d.axis_effects()` 把这条契约量了出来（`tests/test_bg3d_spike.py` 钉住）：

```
beta  → thrust×1.000000  cx×1.183867  cxaoa×0.844690   (cx·cxaoa)×1.000000
gamma → thrust×1.000000  cx×1.000000  cxaoa×1.590091   (cx·cxaoa)×1.590091
dv    → thrust×1.179536  cx×1.000000  cxaoa×1.000000   (cx·cxaoa)×1.000000
```

⇒ `(thrust_scale, cx_scale, cx_scale·cxaoa_scale) ↔ (ΔV, β, γ)` 是**双射**，所以"三根轴互相串了"
这件事在物理上是排除的。`Scan3` 只是把 `Engine` 外面套三层循环（每个 ΔV 一层），
**`engine` 的缓存键、`CACHE_SCHEMA`、`Scaling` 契约一个字都没改**（新模块 `bg3d.py`、
`spikes/bg3d/`，不动 `figures.py`）。

⚠ **口径**：第三根轴是**理想（真空等效）ΔV**（与图1/图2 的 ΔV 同口径，只改 `thrust_scale`）。
仿真量到的 `dv_measured` 系统性更低，两者比值在整块立方体上是
**0.792 ~ 0.880（中位 0.846，相对散布 10.4%）** —— 出图注释必须写清"轴的刻度是理想 ΔV"。

## 2. 两种"等时面"口径：不一样，而且能量出来

| 口径 | 做法 | 面上 `t_hit` 实测散布（场跨度 22.2 s） |
| --- | --- | --- |
| **(a) 真等值面** | `marching_tetrahedra` 直接提 `t_hit(β,γ,ΔV) = L` | **0.0039 ~ 0.0051 s = 0.017 ~ 0.023%**（只剩插值误差） |
| **(b) 拉伸柱面** | 把 ΔV 钉死那一层的 2D 等时线沿 ΔV 拉起来 | **16.36 ~ 17.99 s = 73.6 ~ 80.9%** |

口径 (b) 的数字**与"ΔV 从 600 走到 1100 时 t_hit 的变化"同量级**（固定 β,γ：
`β=3075,γ=56` → 57.71→40.83 s，跨度 **16.88 s**；`β=2550,γ=92` → 61.21→43.14 s，跨度 **18.07 s**），
所以 (b) **不是 `t_hit` 的等值面**，它只是"把二维等时线立起来"，不代表 t_hit 在 ΔV 上的依赖。
两者在图上长得很像（`out/iso/v4_two_flavors.png`），这正是必须把口径写进图注的原因。

基准层：**ΔV = 950 m/s**（PL-12 权威 ΔV = 932.57 的最近格点），该层自带整秒层级 43~47 s；
真等值面用的是 42/44/46/48/50/52 s。

| **coarse** | 11×14×6 | **924** | **21.7 s** | 23.5 | 100% | 39.04 ~ 61.63 s |

- **命中率 100%**（5049/5049）⇒ 立方体里没有"打不到"的洞，等值面不会被 `nan` 挖断。
- 对照既有口径：图2 是 1032 工况 ≈ 20 s（`fast`、缓存空）。**三维的耗时倍数 ≈ 工况数倍数**
  （单工况成本不变），所以代价完全由"网格多大"决定，没有隐藏的额外开销。
- 三轴范围：β 2500~3750（步长 125/75）、γ 44~96（步长 4/2）、ΔV **600~1100**（步长 100/50）。
  范围**显式对齐到整步长**并断言**弹池 11 型全部落在立方体内** —— 2D 的 `make_grid` 是
  "向内对齐"，粗步长下会把 β 下限抬到 2600 而把 R-77（β=2568.8）、Derby（β=2567.0）挤出立方体，

- 提面耗时：6 张真等值面 **101 ms**（共 21820 个三角形）；2 张柱面 **55 ms**。

  而且 5 个变体的 PNG sha256 **逐字节没变**，说明提速没动数值。）

## 4. 画得出来吗：可读性实测

判据不是"我觉得好不好看"，而是把每张面采样投影到屏幕做 **z-buffer**，数
"这张面还有多少格子是它能露头的"（1.0 = 完全没被挡）与"≥2 张面叠在同一格的占比"：

| 变体 | 每张面可见比例 | 互相遮挡格占比 | 结论 |
| --- | --- | --- | --- |
| `v1_one`（1 张） | 1.00 | 0.000 | 当然清楚，但没信息 |
| `v2_three`（3 张） | 1.00 / 0.78 / 0.50 | 0.304 | **3 张是不透明的上限** |
| `v3_six`（6 张，真实跨度） | 1.00 / 0.77 / 0.49 / 0.37 / 0.27 / **0.18** | 0.614 | 糊成一块板（`v3_six.png` 就是） |
| `v8_cube_six`（6 张，**等长三轴** + α=0.45） | 同上（几何没变） | 0.614 | **能数清 6 层**，是唯一可用的静态画法 |
| `v9_cube_cutaway`（4 张 + 剖切面） | 1.00 / 0.78 / 0.50 / 0.38 | 0.425 | 单张面怎么斜，看这张最直观 |

⚠ **画法上有个必须做的选择**：按三轴**真实跨度**给 `box_aspect` 会把盒子压成薄饼
（β 1200 kg/m²、γ 52 kg/m²、ΔV 500 m/s 量纲不同、跨度差 20 倍），6 张近似平行的面就叠成一块；
改成**等长三轴**（刻度照旧是真值）才看得清 —— 这是"图上看着正常、其实白画"的典型。
真实截图（160 dpi，均已在库）：

## 5. 值不值得：ΔV 轴的独立信息量

逐 (β, γ) 列对 ΔV 做最小二乘直线拟合（`bg3d.dv_linearity`，459 列全命中）：

| 量 | 实测 |
| --- | --- |
| 斜率 | **−0.03355 ± 0.00102 s/(m/s)**（相对散布 3.0%） |
| 拟合 `R²` | 中位 **0.9893**（最小 0.9890） |
| 残差 RMS | **0.552 s**（t_hit 跨度 22.2 s，即 2.5%） |
| t_hit 范围 | 39.04 ~ 61.26 s |

也就是说 **`t_hit ≈ a(β, γ) − 0.0336·ΔV`**：等值面在 ΔV 上几乎是**刚性平移**，
一族面近似平行、彼此只差一个 ΔV 偏移。**图上看是三维，独立信息量只有一个斜率**（外加 2.5% 的
曲率）。所以：

- 如果目标是"看 ΔV 有多大影响" ⇒ 一条 `t_hit–ΔV` 直线（或本文这张表）+ 图2 就够了；
- 如果目标是"看不同 ΔV 下 β–γ 能力面的形状变化" ⇒ 2D 切片并排（`v6_slices`）比 3D 好读；
- 真要用 3D，它的价值在"把那一族面一次性摆出来"的**直觉**，不在定量。

**字节可复现**（mplot3d 多面网格，最担心的是深度排序不稳）：

- **同进程连出两次**：9 个变体 × 全部格式 sha256 **逐键一致**（含 6 张半透明的 `v8`）；
- **跨进程 A ↔ B**：9 个变体 × 全部格式 sha256 **逐键一致**（记录在 `out/crossA.json` /
  `out/crossB.json`，判据 `test_cross_process_outputs_are_byte_identical`）。

⇒ 手写 WebGL 这条腿**不是字节复现所必需**的（静态 mplot3d 已经复现），它的价值只在交互。
**这条腿我没做**（见下）。

### 算法自检（零依赖自写的 marching tetrahedra）

| 检验 | 结果 |
| --- | --- |
| Kuhn 6 四面体是否铺满立方体 | 4000 个随机点**每点恰落在 1 个四面体内** ✓ |
| `f = β` 平面等值面 | 所有顶点 β 严格相等，面积 **8.000000**（解析 8）✓ |
| 斜平面 `f = β+2γ+3ΔV` | `max|f−level| = 0`（线性场插值精确）✓ |
| 球面体积（闭合+朝向） | 31³ 1.328% / 41³ 0.750% / 51³ 0.479%（O(h²) 收敛）✓ |
| **三轴跨度不同**的椭球（6×2×4） | 0.642%，朝向一致 ✓ ← 这一条抓到了 `_sample_grad` 的坐标口径 bug |
| `nan` 格子 | 整格跳过，挖空的 γ 层上不出现任何顶点 ✓ |
| 深度依赖 | 源码 AST 里**没有** scipy/skimage/vtk/plotly（只用 numpy + 仓库自己的出口）✓ |

`skimage.marching_cubes` 用不了（本机没装、且分发包要求零新依赖），所以是**手写**：
Kuhn 分解 6 四面体/格、每四面体 16 种符号组合、按"共享顶点走一圈"排序 4 个切点（避免蝴蝶结三角形）。
代价：**21820 个三角形 101 ms**（纯 Python + numpy：格子定位与三线性插值都向量化，没有逐点循环）。
`scipy`/`skimage` 的取舍：装了能省掉这 200 行，但会**改变分发形态**（当前是便携 zip、零二进制依赖），
所以**没有**引入；如果将来要提 32³ 以上的网格，这里会先成为瓶颈（现在不是）。

## 7. **没做到 / 没验证**的（诚实清单）

1. **交互那条腿（手写 WebGL2 前端）没做。** 本会话拿不到可用的委派：
   `spawn_teammate` 只有 Lead 能调（报 "only the Team Lead can create teammates"），
   `subagent` 在本层报 `subagent depth 2 exceeds maxDepth 1`；两条腿都要自己做，
   静态这条已经吃满时间。**几何 payload 与画法结论都已落盘**（`out/iso/iso_surfaces.json` 全量 +
   入库小样），照 `spikes/fig3d/README.md` 的取证流程（headless Edge + swiftshader）可以续做。
2. **只在 fine/coarse 两档网格 + 一个想定上验过**：50 km 迎头、目标 300 m/s 直飞、PL-12 基准、
   `fast` 档、本机 8 并发。换想定（机动目标）后 ΔV 依赖的斜率是否会变，**没测**。
3. **ΔV 轴范围 600~1100 m/s 是拍的**（覆盖弹池 820.5~1099.5），上下边界要不要放宽**没测**；
   边界上等值面会被立方体外表面切掉（`v3_six` 里那些"面超出盒子"的地方就是这个）。
4. **没做分层网格/自适应加密**：现在三轴都是等步长，ΔV 方向只用 6~11 层。
5. **没有把任何东西接进 `figures.py` / `workflow.py` / CLI / WebUI**，也没有新图号（图4）。
   这是 spike，不是交付图。
6. **`box_aspect` 的"等长三轴"是视觉约定**：它不改变数据，但会让面的**视觉倾角**随轴长改变，
   别拿它做角度测量。
7. 面积是**数据坐标下的几何面积**（β 与 γ 都是 kg/m²、ΔV 是 m/s，量纲不同），
   只能在同一轴范围内比较，**不是**物理面积。
