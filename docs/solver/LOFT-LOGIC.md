# 导弹高抛逻辑说明

日期：2026-09-25。本文整理本项目已恢复的普通 loft 高抛分支，以 War Thunder **2.59.0.28 的 AIM-120D** 为主要例子；部分公式和退出历史另有 2.59.0.22 的合成原生实验支持。不同型号、版本及高度保持模式需要分别核对。

高抛的核心是：在条件允许的阶段，根据“期望弹体俯仰角与当前弹体俯仰角的差”生成向上加速度请求，并与常规制导的竖直请求取较大值。目标视线过低或视线转动过快时，高抛退出，后续继续由常规制导控制。

## 1. 三种角度分别表示什么

| 量 | 含义 | 在高抛逻辑中的作用 |
|---|---|---|
| 弹体俯仰角 | 弹头方向相对世界水平面的角度 | 与期望俯仰角比较，生成高抛请求 |
| 航迹倾角 | 导弹速度方向相对世界水平面的角度 | 描述实际爬升或下降；有迎角时与弹体俯仰不同 |
| 目标视线仰角 | 从导弹看向观测目标的方向相对世界水平面的角度 | 判断是否保持高抛 |

本文世界坐标的 `y` 轴向上，向上角度和向上加速度为正。判据使用送入制导外环的观测量；经过滤波时，它们可能与真实几何量存在差异。

## 2. 配置参数

字段位于 `rocket.guidance.guidanceAutopilot`。下列数值来自 2.59.0.28 AIM-120D 资源，含义由对应原生加载器、外环和已有合成实验核对。

| 字段 | AIM-120D 数值 | 含义 |
|---|---:|---|
| `loftEnabled` | `true` | 普通高抛控制器初始化时启用高抛状态 |
| `loftElevation` | 22° | 固定的期望弹体俯仰角 |
| `rangeToLoftElevation` | 未设置 | 可用距离端点与角度端点生成随距离变化的期望俯仰角；本例使用固定 22° |
| `loftTargetElevation` | −3.5° | 保持高抛所要求的最低目标视线仰角 |
| `loftTargetOmegaMax` | 0.95°/s | 保持高抛所允许的最大视线角速度向量模长 |
| `loftAngleToAccelMult` | 5 | 每度俯仰误差对应约 5 m/s² 的高抛加速度请求 |

`loftTargetElevation` 描述退出阈值，不能用作末段俯冲角目标；`loftTargetOmegaMax` 描述目标视线变化，不能用作弹体最大转弯角速度。

## 3. 初始化与每步计算顺序

普通高抛分支有持久状态：`1` 表示高抛有效，`0` 表示未启用或已退出。初始化时根据 `loftEnabled` 设置一次，此后沿用前一步状态。

每次调用制导外环时，按以下顺序理解：

1. 根据弹龄和预计交会时间计算总制导增益 `G`。
2. 若 `G < 0.001`，本步直接输出零控制，不继续正常的 PN、高抛和 PID 更新。这表示控制输出为零，弹体仍继续运动。
3. 计算常规制导请求，包括相应增益和已启用的常规制导分支。
4. 如果高抛状态仍为 `1`，检查目标视线仰角与视线角速度。任一条件失败，将状态改为 `0`；本步使用常规制导请求。
5. 条件通过时，计算期望俯仰角和高抛候选请求，再与常规竖直请求取较大值。
6. 将组合后的请求送入后续限幅、PID 与弹体动力学。

AIM-120D 的 `timeOut` 为 0.6 s，已有案例约在这一时刻启控。具体启控仍由增益表决定，不能把“高抛状态已经初始化为 1”直接理解成发射瞬间已经产生拉起控制。

## 4. 期望俯仰角怎么计算

只配置固定角度时：

```text
期望俯仰角 = loftElevation
```

若设置 `rangeToLoftElevation = [R1, θ1, R2, θ2]`，则按距离平方插值。以下距离单位为米，角度统一用度；先将距离端点及其对应角度一起按距离排序：

```text
比例 = clip((观测距离² - R1²) / (R2² - R1²), 0, 1)
期望俯仰角 = (1 - 比例) × θ1 + 比例 × θ2
```

`clip(x, 0, 1)` 表示把结果限制在 0～1。距离在区间外时取对应端点角度；两个距离端点重合时使用原生退化分支，不能套用上式除以零。AIM-120D 未配置距离变化表，加载后的两个角度端点均为 22°。

距离平方插值与按距离直接插值不同。例如，假设端点为 10 km 对应 10°、20 km 对应 30°，在 15 km 时，比例为 `(225 - 100) / (400 - 100) = 5/12`，期望角度约为 18.33°。这只是说明插值的算例，并非 AIM-120D 参数。

## 5. 高抛请求怎么与常规制导组合

以度为角度单位，计算为：

```text
俯仰误差 = 期望弹体俯仰角 - 当前弹体俯仰角
高抛候选竖直请求 = loftAngleToAccelMult × 俯仰误差
最终竖直请求 = max(常规制导竖直请求, 高抛候选竖直请求)
```

请求单位为 m/s²。高抛分支在此仅修改世界坐标的竖直分量，其余分量保留常规制导结果。组合使用 `max`，不把两个竖直请求相加。这个高抛候选本身不再乘 PN 的总增益 `G`，也不额外乘导弹速度；第 3 节中的总增益启控判断仍然有效。

若内部角度用弧度，等价增益为：

```text
每弧度增益 = loftAngleToAccelMult × 180 / pi
```

以 AIM-120D 为例，假设常规竖直请求为零，且高抛保持条件通过：

| 当前弹体俯仰角 | 高抛候选请求 | 组合后的竖直请求 |
|---:|---:|---:|
| 0° | (22 − 0) × 5 = 110 m/s² | 110 m/s² |
| 10° | (22 − 10) × 5 = 60 m/s² | 60 m/s² |
| 22° | 0 m/s² | 0 m/s² |
| 30° | (22 − 30) × 5 = −40 m/s² | 0 m/s² |

表中最后一行取零，是因为常规请求恰好为零。`max` 不意味着总把负请求截成零：若常规请求为 −20 m/s²、高抛候选为 −40 m/s²，组合结果就是 −20 m/s²。

这一步得到的是控制请求。后面还有请求限幅、PID、迎角与控制量限制，以及气动力、推力和重力等作用。因此请求 110 m/s² 不代表导弹当时实际获得 110 m/s² 的向上加速度，也不能据此直接计算实际过载或最高高度。

## 6. 何时退出，退出后会不会重新开启

对于通常的非竖直目标视线，保持普通高抛需要同时满足：

```text
目标视线仰角 >= loftTargetElevation
视线角速度向量模长 <= loftTargetOmegaMax
```

视线角速度取完整向量的长度，包含水平和竖直方向的变化。目标横向运动也可能使这一阈值被超过。

为了对照原生比较形式，令 `u` 为观测单位视线，`ω` 为视线角速度向量（rad/s），`θ退出` 为退出角（rad），则：

```text
u_y × abs(u_y) >= (u_x² + u_z²) × tan(θ退出) × abs(tan(θ退出))
norm(ω)² <= radians(loftTargetOmegaMax)²
```

任一保持条件失败，状态由 `1` 变为 `0`。**在同一个连续控制器实例内，之后即使条件恢复，也不会自行重新进入高抛。** 不能每帧仅凭 `loftEnabled=true` 重置状态。对象重新初始化或目标重分配是否建立新控制器，属于另外的生命周期问题，本文不将这一结论扩大为全游戏永不重启。

AIM-120D 已有合成边界实验记录：

| 输入条件 | 状态结果 |
|---|---|
| 目标视线仰角 −3.49°，其他保持条件满足 | 保持高抛 |
| 目标视线仰角 −3.51° | 退出高抛 |
| 视线角速度 0.949°/s，其他保持条件满足 | 保持高抛 |
| 视线角速度 0.951°/s | 退出高抛 |
| 退出后把视线仰角和角速度恢复为零 | 仍保持退出状态 |

阈值附近以原生 float32 运算和实际观测输入为准，显示值的四舍五入可能遮住跨阈值的微小差异。

## 7. 为什么退出高抛后还会继续爬升

退出高抛只会停止该分支对请求的修改，不会立即清除向上速度。导弹仍可能继续爬升一段时间，之后才到达最高点。

已有 AIM-120D 离线案例：初始斜距 60 km，双方高度均为 6000 m，导弹初速 300 m/s，目标以 250 m/s 直线迎头飞行。

| 时刻 | 已记录行为 |
|---|---|
| 约 0.6 s | 制导启控后开始明显拉起 |
| 12.700 s | 高抛退出；高度约 8892.58 m，观测目标仰角 −3.500341°，视线角速度 0.468534°/s |
| 同一退出步 | 由仰角阈值触发退出；竖直请求转为约 −31.52 m/s²，但仍有向上速度 |
| 约 25.4 s | 在 0.1 s 输出采样中达到最高点，约 10630.40 m |

这些是已有离线原生调用与合成场景的结果，不是游戏实测。仅凭弹道仍在上升，无法判断内部高抛状态仍然有效。
