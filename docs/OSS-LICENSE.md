## 0. 先说三件让这个项目的许可选择比一般项目简单的事

1. **公开集里不含游戏数据、不含第三方内核。** `vendor/wt-missile/**`（内核源码 142 KB +
   168 份 `.blk`）与 `results/reference_fig.png` 都会移出公开集（见 `OPENSOURCE-READINESS.md` §2/§3），
   所以"许可"只覆盖**本仓库自己写的代码 + 自己生成的产物**，没有第三方资产的授权问题混进来。
2. **运行时依赖全是宽松许可，没有一个是 copyleft。** Python 本身是 PSF-2.0，`numpy` 是 BSD-3-Clause，
   `matplotlib` 是 PSF 系的 BSD 兼容许可；`make_dist.py` 只做 zip + 复制（不打包 PyInstaller 这类工具）。
   ⇒ 我们**选 MIT 不会有"与依赖冲突"的问题**（这点在选了 GPL 的项目里经常要额外解释）。
3. **免责声明与许可无关，无论选哪个都要留着。** "独立社区项目、与 Gaijin 无关"、
   "产物是仿真结果不是游戏内实测值"、"War Thunder 是 Gaijin 的商标"这些写在 `README.md` §9，
   属于**事实声明**，不因为换许可而改变。

## 1. 三个候选的差别（只列会影响我们的）

| 维度 | **MIT** | **Apache-2.0** | GPL-3.0（不推荐） |
| --- | --- | --- | --- |
| 别人能不能闭源再分发 | 可以 | 可以 | **不行**（衍生作品必须也 GPL-3.0） |
| 专利授权 | **没有明说**（只有默示授权，判例法兜底） | **第 3 条显式授予 + 报复条款**（你告我专利，我对你的授权终止） | 第 11 条显式授予 |
| 商标授权 | 不涉及 | 第 6 条**明确不给**商标权 | 第 7 条不给 |
| 改动声明义务 | 无 | **要**：改过的文件需注明"已修改"，且要带 `NOTICE` | 要（且有源码提供义务） |
| 要维护的文件 | `LICENSE` 一份 | `LICENSE` + `NOTICE`（含归属与变更说明） | `LICENSE` + 源码提供方式 |
| 正文长度 | 约 170 词 | 约 1500 词 | 约 5700 词 |
| 与本项目的契合度 | 高：研究/教学工具，最容易被拿走复用 | 中高：多一层专利与归属保护 | **低**：我们这个"内核是 all-rights-reserved 的第三方代码"的处境下，GPL 会把"整体分发合规"抬成必须解释的负担 |

## 2. 三个"具体到我们"的判据（自己勾一下就有答案）

| 场景 | MIT | Apache-2.0 | GPL-3.0 |
| --- | --- | --- | --- |
| A. 有人把 `mapping.py` 的 ΔV·BC ↔ 乘数公式抄进**闭源商业软件** | ✅ 允许 | ✅ 允许（带 NOTICE） | ❌ 不许，会逼对方开源 |
| B. 你担心有人拿这套东西**申请专利反过来卡你** | ⚠️ 只有默示授权 | ✅ 显式授权 + 报复条款 | ✅ 显式授权 |
| C. 有人拿去做**在线服务（SaaS）**不回馈社区 | 拦不住 | 拦不住 | 拦不住（要拦得用 AGPL，**不推荐**） |

> 结论方向：**你在意 A（传播越广越好）就选 MIT；你在意 B（怕被专利卡）就选 Apache-2.0。**
> C 不是这两个许可能解决的问题，选 AGPL 会让"研究者拿去做课程作业"都变得麻烦，不划算。

## 3. 我的推荐：MIT

1. **本项目的价值在文档 + 可复现产物 + 公式实现，不在代码本身。** 最宽松的许可能让做同类研究的人
   直接搬 `mapping.py` / `bg.py` 的公式，这正是项目目的；
2. **与"内核不进仓库"这件事的兼容性最好**：MIT 只覆盖我们自写的东西，不需要像 GPL 那样
   解释"内核算不算整体分发的一部分"；
3. **社区预期**：这类离线可复现的研究工具，MIT 是默认答案，别人不会因为许可问题犹豫。

**什么时候改选 Apache-2.0**：如果你希望公开后**有人正式引用/给大厂内部使用**，或者你就是
在意"专利被反咬"这条 —— 代价是每次改文件要注明修改、维护一份 `NOTICE`，对一个人维护的项目是纯负担。

## 4. 拍板后要改的地方（只有三处，都已有占位）

| 文件 | 现在 | 拍板后 |
| --- | --- | --- |
| `LICENSE` | 占位（明确写着"这不是许可证"） | 换成该许可的**标准英文正文，一字不改**；`Copyright (c) 2026 <你的名字或 ID>` |
| `pyproject.toml` | **刻意不写** `license` 字段 | `license = "MIT"`（或 `"Apache-2.0"`）+ 需要时补 `classifiers` |
| `README.md` §9.5 | 写着"许可待定" | 写清许可类型与一句"见 LICENSE" |

可选：`pyproject.toml` 里加 `license-files = ["LICENSE"]`（PEP 639 风格）；
Apache-2.0 还要新增 `NOTICE`。

**换什么许可都解决不了它的授权问题** —— 只能二选一：移出公开集，或先向原作者要一句授权
（`OPENSOURCE-READINESS.md` §3.2 已实测：移出对测试 **0 影响**）。既然已经"先私有跑一周"，
这一周里顺手问一句授权是最省事的做法。
